Статический сайт (index.html) + ежедневное обновление котировок Мосбиржи (GitHub Actions) + необязательный
Telegram-дайджест по вашему плану. Серверов и платных сервисов нет.

## Файлы
- `index.html` — приложение (внутри встроен файл офз.xlsx на случай, если data.json недоступен).
- `data.json` — котировки, перезаписывается скриптом по будням в 19:00 по Москве.
- `ratings.json` — рейтинги корпоративных выпусков: `"Название": "AA-"`. Можно править вручную.
- `scripts/update_data.py` — обновление данных с ISS Мосбиржи. `scripts/digest.py` — дайджест в Telegram.
- `.github/workflows/update.yml`, `digest.yml` — расписания. `sw.js`, `manifest.webmanifest`, `icon-*.png` — установка на телефон.

## Обновление уже работающего репозитория
1. Загрузите файлы из `bond-app-update.zip`: Add file → Upload files (index.html, sw.js, manifest.webmanifest,
   icon-192.png, icon-512.png, LICENSE, README.md и папку scripts). **Не загружайте data.json и ratings.json из полного
   архива**: в репозитории они свежее.
2. Файл `.github/workflows/digest.yml` создайте вручную: Add file → Create new file, имя `.github/workflows/digest.yml`,
   текст возьмите из одноимённого файла в архиве.
3. Запустите Actions → Update bond data → Run workflow, чтобы данные пересобрались с новыми полями (признак «для квалифицированных»).

## Что нового в приложении
- **Журнал сделок.** В «Моём плане» записывайте покупки (штуки, цена, НКД, комиссия, дата). Приложение считает вложенное, стоимость
  сейчас, оценку полученных купонов и годовую доходность. Пополнения кнопкой «Распределить» попадают в журнал сами.
- **Оферты.** Галочка «Считать до оферты»: срок и доходность считаются до даты оферты по цене 100%. У коротких оферт
  доходность выглядит завышенной, это особенность расчёта, а не ошибка.
- **Квалифицированный инвестор.** Выпуски «только для квалов» скрыты, пока галочка не стоит. Признак берётся из данных биржи, если она его отдаёт;
  в логе обновления есть строка «для квалифицированных» и список колонок. Если там 0, признак надо проверять вручную.
- **Ручные рейтинги** для выпусков без рейтинга: вписываются прямо в списке «Выбрать бумаги самому», хранятся в браузере.
- **Чувствительность к ставке** (±1 и ±2 п.п.) и **издержки покупки** (комиссия и спред) в расчёте количества бумаг.
- **Несколько планов** (ИИС, брокерский и т.д.) со своим налоговым режимом. **Экспорт и импорт** планов файлом JSON:
  так их можно перенести на другое устройство, потому что план хранится в браузере.
- **Установка на телефон**: в меню браузера «Установить приложение» или «Добавить на главный экран».

## Telegram-дайджест (по желанию)
Присылает выплаты на ближайшие 7 дней, погашения и оферты на 30 дней и сильные движения цены по бумагам, которые вы отметили купленными.
1. В Telegram найдите @BotFather, команда `/newbot`, получите токен.
2. Напишите своему боту любое сообщение, откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": ...}`.
3. В репозитории: Settings → Secrets and variables → Actions → New repository secret. Создайте три секрета:
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и `PLAN_JSON` (весь текст файла из кнопки «Экспорт» в приложении).
4. Actions → Daily digest → Run workflow для проверки. По будням в 09:00 по Москве сообщение придёт, если есть о чём.
5. Обновлять `PLAN_JSON` нужно после изменений плана.

**Приватность.** Репозиторий публичный, поэтому не кладите файл плана в репозиторий: только в секрет. В секретах он не виден посторонним.

## Что нового в версии 24.10.2026-3

- **Доходность с поправкой на риск**: ожидаемые потери от дефолтов по рейтингу (мягкая, базовая и жёсткая модели, свой возврат при дефолте). Допущения условные, их список в блоке «Допущения расчёта». Галочка «Отбирать по доходности с поправкой на риск» меняет и сам подбор.
- **Кривая доходности и премия к ОФЗ**: график, колонки в таблицах и сортировка по премии.
- **Фильтры в ручном выборе**: доходность, срок, рейтинг, частота выплат, только с офертой и сортировка по семи признакам.
- **Календарь выплат (.ics)** в блоке «Мой план»: купоны, погашения и оферты на 36 месяцев с напоминанием за день. Откройте файл на телефоне, и события добавятся в календарь.
- **История цен**: скрипт обновления ежедневно дописывает цены и доходности в `history.json` (250 дней, выпуски с рейтингом и ОФЗ). В плане появляются график стоимости купленного и графики цены и доходности по бумаге. История копится с первого запуска нового скрипта.
- **Ребалансировка**: плану подсказывает, что поправить: рейтинг упал, цена обвалилась, бумага исчезла из торгов, скоро оферта, доли разошлись с планом, и предлагает похожие замены.

## Что нового в версии 24.10.2026-4
- **Импорт отчёта брокера** (блок «Журнал сделок» в плане): файлы xlsx, xls, csv. Приложение само ищет строку заголовков (дата, наименование, операция, количество, цена, НКД, комиссия), распознаёт покупки и продажи, переводит цену из рублей в проценты, пропускает дубликаты и сообщает, какие бумаги не нашлись. Разбор общий, под конкретного брокера он не проверялся: если файл не распознаётся, пришлите образец с замазанными данными счёта.
- **Сохранённые поиски и оповещения.** В «Выбрать бумаги самому» можно сохранить набор фильтров под именем. В плане (блок «Оповещения») задаются условия «доходность не ниже» и «цена не выше». Telegram-дайджест присылает новые выпуски по поискам и сообщает, когда оповещение начало выполняться. Для этого нужен свежий экспорт планов (кнопка «Экспорт») в секрете `PLAN_JSON`, а в `digest.yml` должен быть шаг сохранения `state.json` (см. ниже).
- **Мобильные вкладки** «Подбор», «Рынок», «План» внизу экрана; панель параметров сворачивается; в таблицах первый столбец закреплён при прокрутке вбок.
- **Сравнение с вкладом и фондом ликвидности**: введите их доходность слева, и приложение покажет разницу и доход за срок.
- **Путь ключевой ставки** (например, `2027-01:12, 2027-07:10`): купоны плавающих ОФЗ считаются по этому пути. **Симуляция дефолтов**: 2000 сценариев, разброс итогового результата, вероятность недополучить вложенное.
- **Синхронизация через приватный Gist** (в блоке «Планы»): нужен токен GitHub (classic) только с правом gist. Токен хранится в браузере. Выгружаются планы, поиски и оповещения.
- **ЛДВ**: галочка у плана. Доход от погашения (разница между номиналом и ценой покупки) по бумагам, которыми вы владеете от 3 лет, не облагается налогом. Лимит 3 млн ₽ за каждый год владения не проверяется, купоны льготой не покрываются. Убытки с продаж в налоге пока не зачитываются.

### Обновление `digest.yml` (только если используете Telegram)
В `.github/workflows/digest.yml` после `jobs:` блок `permissions: contents: write` должен стоять на верхнем уровне, а в конец шагов добавьте:
```
      - name: Save digest state
        run: |
          git config user.name "bond-bot"
          git config user.email "bond-bot@users.noreply.github.com"
          if [ -f state.json ]; then git add state.json; fi
          git diff --cached --quiet || git commit -m "Digest state"
          git push
```
Готовый файл лежит в архиве.

## Что нового в версии 24.10.2026-5
- **Планировщик пополнений** (блок «Мой план»): вы задаёте сумму, периодичность (раз в месяц, квартал, год или разово) и число пополнений. Приложение составляет график покупок: сначала докупает бумаги плана, начиная с самых отстающих, а когда план собран, предлагает новые бумаги в рамках ваших параметров подбора (риск, срок, рейтинг, лимит эмитента, комиссия). - **Рекомендации** под графиком: когда будет собран план, где в лесенке пропущен год и какую бумагу взять, в каких месяцах нет выплат, не вырастет ли доля эмитента выше лимита, не ухудшились ли рейтинги.

## Что нового в версии 24.10.2026-6: автоматическая синхронизация
Планы, сохранённые поиски, оповещения и ручные рейтинги теперь можно держать одинаковыми на ноутбуке и телефоне.

**Настройка (один раз на каждом устройстве)**
1. На github.com: Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token. Отметьте только право `gist`, срок выберите по желанию. Скопируйте токен.
2. В приложении откройте блок «Планы» → «Синхронизация между устройствами». Вставьте токен и придумайте кодовую фразу (на всех устройствах одинаковую). Нажмите «Включить и синхронизировать».
3. На втором устройстве сделайте то же самое с тем же токеном и той же фразой. Идентификатор Gist вводить не нужно: приложение само находит нужный.

**Как это работает**
- Данные шифруются на устройстве (AES-256, ключ из кодовой фразы) и только после этого уходят в ваш Gist на GitHub. Секретные Gist доступны каждому, у кого есть ссылка, но содержимое там нечитаемо без фразы. Фразу не потеряйте: восстановить данные без неё нельзя.
- Изменения отправляются автоматически через пару секунд. При открытии страницы и при возвращении на неё приложение подтягивает свежие данные.
- Если на двух устройствах менялись разные планы, они объединяются. Если один и тот же план, побеждает более поздняя правка. Удалённый план удаляется везде. Поиски и оповещения берутся из более поздней версии целиком.
- Токен и фраза хранятся в браузере устройства. Если устройство потеряно, отзовите токен на GitHub (Settings → Tokens) и смените фразу.
- Если вы пользовались ручной выгрузкой из версии 24.10.2026-4, она сохраняла файл без шифрования: откройте gist.github.com, найдите Gist с файлом `bond-plans.json` и удалите его.
- Telegram-дайджест по-прежнему читает план из секрета `PLAN_JSON`, он не синхронизируется сам.

## Что нового в версии 24.10.2026-8: график выплат «план и факт»
В блоке «Мой план» появился график по месяцам (до 11 прошлых и 11 будущих месяцев).
- **План** (широкий жёлтый столбец): выплаты после налога, которые приходили бы, если бы весь план был куплен в день создания.
- **Факт** (узкий основной столбец): выплаты по тому, что вы реально купили, по журналу сделок с учётом дат покупок и продаж. Для будущих месяцев столбец штриховой: это ожидание по купленному сейчас.
- Под графиком таблица прошлых месяцев: план, оценка факта и поле «Получено, ₽». Впишите сумму из отчёта брокера, и оценка этого месяца заменится вашей цифрой. Пустое поле возвращает оценку. В итоге показано, сколько процентов от плана получено.
- Налог берётся по настройкам плана (режим, другие доходы, ЛДВ). Для плавающих ОФЗ в прошлом используется купон, сохранённый в плане.

## Что нового в версиях 24.10.2026-9 и -10
- **Цветная инструкция.** Кнопка «Инструкция» в шапке открывает окно с разделами по цветам: быстрый старт, параметры подбора, чтение графиков, ручной выбор, план, синхронизация, данные, Telegram, частые вопросы. Окно закрывается кнопкой, клавишей Esc или щелчком по фону, подстраивается под выбранную тему.
- **Выпуски для квалифицированных инвесторов исключены всегда.** Переключатель «Я квалифицированный инвестор» убран, такие выпуски не попадают ни в подбор, ни в ручной список, ни в планировщик, ни в замены ребалансировки, ни в Telegram-дайджест.
  - *Откуда берётся признак.* Скрипт обновления после загрузки котировок спрашивает у биржи описание каждого корпоративного выпуска (поле о квалифицированных инвесторах) и хранит ответы в `data.json` (раздел `qc`), поэтому повторные запуски быстрые. Первый запуск делает около 1500 запросов и идёт 1–3 минуты.
  - *Если признак определить не удалось.* В логе будет строка `Квалифицированные: ... проверка: unknown` (биржа не отдаёт поле) или `partial` (по части выпусков запрос не прошёл). Выпуски с неопределённым статусом при `partial` на этот запуск убираются и перепроверяются в следующий. При `unknown` проверить автоматически нельзя: на странице появляется предупреждение, а сомнительные выпуски убирают кнопкой «Скрыть».
  - *Кнопка «Скрыть»* в списке бумаг убирает выпуск из всего подбора и синхронизируется между устройствами; список скрытых и кнопка «Вернуть» находятся над таблицей.
- **Данные с `data.json`, обновлённые до этой версии скрипта, признака не содержат**, поэтому страница показывает предупреждение, пока вы не загрузите новый `scripts/update_data.py` и не запустите Actions → Update bond data.

## Версии 24.10.2026-14 и -15: надёжность, простой режим, отчёт
**Надёжность**
- **Автотесты.** В папке `tests` лежат 200+ проверок логики страницы (`node tests/run-all.js`), тесты скриптов (`python -m unittest discover -s tests -p "test_*.py"`) и тест в настоящем Chrome (`tests/e2e`, Playwright). Workflow `Tests` запускается при каждой загрузке файлов, `Browser test` проверяет страницу в Chrome при изменении `index.html` (и вручную). В Chrome проверяются 4 размера экрана (телефон, планшет, ноутбук, монитор): нет ли ошибок, нет ли горизонтальной прокрутки всей страницы, не закреплена ли панель на телефоне, работают ли тема, простой режим, инструкция, «Скрыть», план и отчёт. Файл `tests/fixture.json` это неизменные данные для проверок.
- **Сигналы о сбоях.** Если данные на странице старше 3 суток (выходные не считаются сбоем), вверху появляется предупреждение. Если обновление на GitHub упало, приходит сообщение в Telegram (нужны секреты `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`). Если выпусков в ответе биржи стало на 30% меньше, чем в прошлый раз, скрипт данные не перезаписывает и сообщает об этом. Дайджест добавляет предупреждение, когда данные не обновлялись больше 3 суток.
- **Проверка формул.** Тесты сверяют доходность с аналитическими примерами (нулевой купон, облигация по номиналу, полугодовые купоны), прогрессивную шкалу НДФЛ (312 000, 702 000, 3 402 000, 9 402 000 и 11 602 000 ₽ на границах), налог на дисконт, календарь купонов и совпадение расчёта в JavaScript и Python. Проверка нашла и исправила две ошибки: платёж, назначенный на 29–31 число, при переносе на короткий месяц «перескакивал» в следующий, а если дата ближайшего купона в данных уже прошла, доходность считалась завышенной. Скрипт обновления теперь пишет в лог «Сверка доходности»: медианное расхождение с биржей и выпуски с наибольшим расхождением.

**Удобство и аналитика**
- **Простой режим** (кнопка в шапке): сумма, число бумаг, горизонт, риск, стратегия и блок «Простыми словами» вместо десятка графиков. Расширенные блоки скрыты и возвращаются кнопкой.
- **Отчёт (PDF)** из блока «Состав портфеля» и из «Моего плана»: откроется окно печати, выберите «Сохранить как PDF».
- **Ранние сигналы по истории цен:** если цена бумаги за 5 наблюдений упала на 3 п.п. и больше относительно медианы рынка (и минимум на 2 п.п. сама), это видно в «Ребалансировке» и в Telegram-дайджесте. Нужны 6 и больше дней в `history.json`.
- **Подсказки по продаже и замене:** близкие погашения и оферты, а также считает, окупается ли замена бумаги на более доходную того же срока и не хуже по рейтингу, с учётом комиссии и налога.
- **Реальная доходность:** поле «Ожидаемая инфляция» добавляет «Реальную после налога» в итоги и в сравнение с вкладом.
- **ОФЗ-ИН не добавлены сознательно:** для них нужен коэффициент индексации номинала, которого нет ни в вашем файле, ни в данных, читаемых скриптом. Без него цены и купоны были бы посчитаны неверно.

### Что загрузить в репозиторий
Из `bond-app-update.zip`: `index.html`, `README.md`, папки `scripts` и `tests`. Файлы `.github/workflows/tests.yml`, `e2e.yml` и обновлённый `update.yml` создайте вручную (Add file → Create new file, имя вида `.github/workflows/tests.yml`, текст из архива). Файлы `data.json`, `ratings.json` и `blocklist.json` не перезаписывайте.

## Ограничения
- Расчёт ведётся для облигаций с номиналом 1000 ₽ с известным купоном; индексируемые и амортизируемые выпуски исключены.
- Рейтинги ISS не отдаёт, они берутся из ratings.json, остальные выпуски скрыты в профилях риска.
- Доходность может отличаться от smart-lab в десятых долях процента. Налог в плане показан в месяц получения дохода.
- GitHub отключает расписание в репозиториях без активности 60 дней; тогда включите workflow заново.
